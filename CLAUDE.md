# Sound-Babound: notes for contributors

A Rust tray soundboard. Plans live in `docs/plans/`.

## Crate layout

- `crates/engine` (`babound-engine`): has no UI dependencies. Its modules are private. `lib.rs` re-exports only what the app needs: `Engine`, `MicSettings`, `MicStatus`, `CaptureStatus`, `MicProbe`, `probe_mic`, `Sound`, `StreamInfo`, `DeviceIdentity` (so app tests can build a `StreamInfo`), `StreamRole`, `StreamStatus`, `DeviceEvent`, `RebuildPolicy`, the error types (with `BuildErrorKind`) and `VERSION`. Items that only tests use are `#[cfg(test)]`.
  - `error.rs`: `LoadError`, `BuildError` (including `DeviceNotFound` for an unmatched mic sink pattern and `FeedbackExcluded` for a refused capture), `StartError`, `WatcherError`.
  - `sound.rs`: symphonia decode into a cheap-clone `Sound` (`Arc<SoundData>`).
  - `mixer.rs`: the realtime mixer, the command queue and the garbage queue. The mic sink's mixer (`Mixer::with_passthrough`) owns a `PassthroughReader` and adds `input gain × passthrough` before the clamp, with the mono-sound mapping; the monitor's mixer (`Mixer::new`) has none. `Command::SetPathGains { sound, input }` sets the per-path gains (default 1.0). `MixerShared::silence` silences a path for good: every later render outputs silence (it still applies commands and releases sounds).
  - `convert.rs`: f32 to device sample format (`OutputSample`). Every cpal PCM format is supported. I24 and U24 go through i32, because dasp overflows them at +1.0. `InputSample` is the reverse (device format to f32) for the capture.
  - `passthrough.rs`: the mic passthrough. `PassthroughShared` holds a mono `ArrayQueue<f32>` ring (0.5 s at 192 kHz) that the capture writes to. `PassthroughReader`, owned by the mic mixer, primes to the effective target (30 ms, or more for long device blocks) and resamples by linear interpolation. A PI controller, clamped to ±0.2 %, adjusts the ratio to hold the fill. Drift tests simulate both device clocks. `close()` empties the ring and drops every later write (the heartbeat still moves).
  - `sink.rs`: `StreamRole`, the `StreamFactory`, `Endpoint` and `ActiveStream` traits, `MixerEndpoint` (the endpoint of both output roles) and `CaptureEndpoint` (around `PassthroughShared`).
  - `cpal_sink.rs`: `CpalOutputFactory`, the cpal output factory of both output roles. `OutputTarget::Default` is the monitor (the default output of `platform::monitor_host()`); `OutputTarget::Named { pattern, prefer }` is the mic sink, chosen by the pure `best_match`: among the outputs of `platform::mic_host()` whose display name or id contains the pattern (ignoring case; a blank pattern matches nothing), the first, in enumeration order, that the preference names too, otherwise the first match. `MicSettings::device_prefer` is the preference, and it counts in `same_streams`. Both re-query on every build and identity query. `probe()` resolves the device and its default config without a stream. It also holds the helpers the capture shares: error mapping, `identity_of`, `device_name`, `name_matches` and the pure `mic_buffer_size`. `device_name` reads the device's description (falling back to its id); never format a `cpal::Device` with `Display`/`to_string`, which panics for a device that just went away. The mic sink and the capture (not the monitor) ask for `mic_buffer_size(supported, rate, platform::MIC_PERIOD_MS)`: that many milliseconds of frames clamped to the device range, or the backend default without a period or a range.
  - `capture.rs`: `CpalCaptureFactory`, the capture on the default input of `platform::mic_host()`. The pure `InputSelector` wraps `choose_input` and remembers the last default input it chose as the last physical one. `choose_input` refuses an input that an exclusion names (the virtual device or its monitor): it falls back to the last physical default input if it is still present, otherwise the build fails with `FeedbackExcluded` and the supervisor retries. `NoticeLog` warns once per change of that decision. A build calls `begin_capture(rate)` before the stream starts.
  - `platform/`: the cpal host per role. The monitor uses the default host, except ALSA on Linux (as in stage 1, since the `pulseaudio` feature makes PulseAudio cpal's Linux default; if ALSA cannot open, the shared PulseAudio host). The mic paths use the default host, except PulseAudio on Linux (falling back to ALSA by id). Linux never uses cpal's default host, which tries PulseAudio first, unprobed, and would hand out an unshared PulseAudio host. `monitor_host()` and `mic_host()` return an `Option<Arc<cpal::Host>>`: `None` (only on Linux) when no host opens, which fails the build (`cpal_sink::opened`) or reads as no answer in a poller. On Linux it is one PulseAudio host for the whole process, kept in the pure `SharedHost` (`shared_host.rs`), which hands out the kept host while a liveness check (`devices()`) passes and otherwise reconnects once and keeps the new host. A connect is tried only after `pulse_server_answers` saw the server answer the whole handshake cpal's connect makes (`Auth`, then `SetClientName` at the negotiated version) over a socket of its own (a non-blocking `socket2` connect that fails at once on a full backlog (`EAGAIN`) and waits out an `EINPROGRESS`; the whole probe has one 2 s deadline (`PROBE_TIMEOUT`) over the connect and both messages, and every read and write sets its socket timeout to the time left, so even a server that trickles bytes ends the probe at most one poll (`CONNECT_POLL`, 5 ms) past the deadline; an error reply counts as answering): cpal's PulseAudio host gives up on a handshake after 2 s but leaves its connecting thread blocked, so retrying against a server that accepts but never answers would leak a thread per try. The probe runs inside `SharedHost::get`'s connect, under its lock, so probes and connects never overlap. The decision is the pure `try_connect` (`shared_host.rs`, tested on every OS): nothing while the `Backoff` holds off, then the probe, then the connect. A failed probe (logged at debug) arms the hold-off through `Backoff::probe_failed`, since a timed-out one blocks every mic caller behind that lock for at most the probe's deadline, but never counts as a stalled connect. A server can still answer the probe and stall cpal's connect right after it, so a connect that fails after a passed probe starts the hold-off too (`Backoff::failed`): no probe or connect for 2 s, doubling per failure in a row (failed probes and connects alike), reset by a successful connect. A hold-off made only of failed probes stops at `PROBE_HOLD_OFF_MAX` (10 s), so a server that comes up is noticed within that; a streak with a failed connect (`Backoff::connect_failed`) keeps doubling up to 60 s (`BACKOFF_MAX`), also for the probe failures after it. A failed connect that took at least `STALL_THRESHOLD` (1.5 s) stalled and leaked a thread; after `MAX_STALLED_CONNECTS` (8) of them, counted for the whole process (a successful connect does not reset the count), no PulseAudio connect is tried again until the app restarts and the mic paths fall back to ALSA, so at most that many threads ever leak. A dropped PulseAudio host leaks its reactor thread and server connection, so mic builds, failed-build retries, probes, identity queries, the capture and mic sink pollers and mic restarts all share this one; only the connection is kept, never a device. `MIC_PERIOD_MS` is the mic paths' stream period: `Some(10)` on Linux, because with the default buffer size the PulseAudio server picks about 2 s fragments, which the passthrough cannot use; `Some(10)` on macOS, because CoreAudio's default is the device's current buffer, which a DAW may have set to 1024–4096 frames (the passthrough's adaptive target still covers a device that cannot go lower); `None` (the host default) on Windows.
  - `supervisor.rs`: the pure `SupervisorCore` state machine, the pure `FailureLog` build-failure throttle, `StreamStatus`, and the one generic supervisor thread (`spawn_supervisor`), one instance per role, each starting its own watcher. A shutdown waits at most `Timings::stop_timeout` (3 s) for the thread: a build or identity query blocked on a PulseAudio server that stopped answering (its requests have no timeout) is left to finish, and the thread then stops on the queued shutdown, so mic off and app exit never hang. The engine stops its supervisors with `SupervisorHandle::shutdown_all`, which tells every thread to stop first and then waits for all of them against one deadline, so mic off and `Engine::shutdown` each wait at most one stop timeout in all (the single-handle `shutdown` is test-only). `shutdown_all` returns the threads it left running (they may still hold their stream); the engine keeps the mic ones (including a mic sink it shuts down because the capture's thread could not be spawned), and `Engine::mic_stopped` is false until they have ended. `Engine::shutdown` returns whether every supervisor thread has ended, those included.
  - `watcher/`: OS device-change listeners, one per supervisor, picked by `platform_watcher(role)`. `poll.rs` is the shared polling watcher: a thread that runs a query every interval and, when the answer changes, sends the event a caller's function builds from the previous and the current answer (the first answer is the baseline; the pure `ChangeDetector`; a late first answer has no previous one). `start` returns once the baseline is in, so the supervisor's first build is never newer than it. A hung query never blocks the supervisor for long: `start` and the guard's drop each wait at most a stop timeout (2 s on Linux), and dropping the guard stops the thread and joins it, or leaves a still-running query to finish and exit on its own without sending. If `start` gave up on the baseline, the first answer is sent as a change, since the supervisor may have built on an older one. Every query holds a gate the caller shares between its pollers (on Linux one process-wide gate for the capture's pollers and one for the mic sink's), so a new poller waits behind a hung one, checking its stop signal, and at most one hung query thread per gate is ever left behind. `inputs.rs` is the Linux capture poller's pure query: `InputsQuery` asks a kept `InputHost` for an `InputsSnapshot` (the default input and the sorted input list), keeps only a host that answers and wants keeping (the shared PulseAudio host, not a fallback), and asks a fresh host from its `connect` in the same poll when the kept one's connection fails, so a reconnect does not read as two changes. `change_event` maps a new default (or a late first answer) to `DefaultInputChanged` and any other change to `DeviceListChanged`. The Linux mic sink poller runs the same query over the output list (no default, through the `OutputList` host wrapper in `linux.rs`), and `list_change_event` maps every change to `DeviceListChanged`.
  - `engine.rs`: the public `Engine` API (non-blocking queue pushes and atomic reads). The monitor always runs. `set_mic(&mut self, Option<MicSettings>)` starts, stops or restarts the mic sink and capture supervisors (a gains-only change just sends `SetPathGains`, and the new settings are stored only once it was queued, so a full queue is retried by the next call); the monitor is never touched. A start or restart while a stopped mic supervisor thread is still running (`mic_stopped` false) is deferred: the settings are kept as pending, `mic_status` reports `Starting`, and `Engine::resume_mic` starts the path once every stopped thread has ended, so a new mic path never runs beside an old one that may still hold its streams (a capture turned off could otherwise keep carrying the live microphone); `set_mic(None)` cancels a pending start. Every mic stop (and dropping the path) first silences the path through its `Silencer`: the mic sink's `MixerShared::silence` and the passthrough's `close`, so a stream a timed-out stop leaves running (its supervisor blocked in a device query) carries neither sounds nor the microphone. The engine remembers the last `set_master_gain` value and queues it, with the path gains, on every mic path it starts. `play` fans out to every path that accepts plays (true if any did); `stop_all` and `set_master_gain` go to every path. `CaptureStatus::Unavailable { kind, error }` carries the capture build failure's `BuildErrorKind` next to its text, so the tray can say why (the supervisor's `StreamStatus::Failed` keeps the kind too). Factories and watchers come from the `Backends` trait: `CpalBackends` in production, `FakeBackends` in tests. `probe_mic` resolves the mic devices without building a stream.
  - `test_support.rs` (`#[cfg(test)]`): `FakeSinkFactory`, `FakeCaptureFactory`, `FakeBackends`, `FakeWatcher` and `wait_until`.
  - `testdata/`: tiny FLAC, OGG Vorbis and MP3 fixtures for the decode tests. The ffmpeg commands that made them are in the `fixture` helper's doc comment in `sound.rs`.
- `crates/app` (`sound-babound`): the binary.
  - `main.rs`: the Windows GUI subsystem, plus attaching to the parent console when any argument is given.
  - `logging.rs`: `tracing` to stderr, with an `EnvFilter` read from `RUST_LOG` (default `info`).
  - `cli.rs`: the clap CLI, headless `play`, `mic-check` and `settings` (which `main` dispatches to `settings::run()`; no arguments). `play [file] [--output-only]`: `load_play_sound` resolves a UTF-8 argument through `SoundSource::resolve(text, Path::new(""))`, so `builtin:<name>` works like in the config and relative paths stay relative to the working directory (a non-UTF-8 path stays a file, no argument is the demo entry, an unknown built-in fails naming the available ones). `--output-only` plays on the default output only, never into the virtual mic: the pure `play_mic_config(mic, output_only)` turns `enabled` off before logging and `play_to_end`, so neither the mic sink nor the mic wait starts. `play` and `mic-check` read `[mic]` without creating the config file (a missing or malformed file means the defaults, with a note); `settings` creates it through `paths::ensure_default_config`, like the tray. `play` with the mic enabled starts the mic path without capture and without the Linux device, waits up to 3 s for the mic sink (otherwise it warns and plays on the monitor only), and waits for the play to be applied once per running path. `mic-check` reports through `mic_report` and exits non-zero unless the virtual device is found and the microphone can be captured; it opens no stream.
  - `mic_report.rs`: the virtual mic report that `mic-check` prints and the settings window shows: `MicCheck`, `MicReport`, the pure `format_mic_check` (fed a `MicProbe`, whose `excluded_default` names an excluded default input; that line says the tray's capture stays on the last physical input it used, if there was one, since a fresh probe knows none), `describe`, `access_text` and `mic_config_at` (reads `[mic]` without creating the file). `run_mic_check` and `status_check(path)` (the window's refresher) share `check_with`, which takes the probe as a closure so tests use a fake one.
  - `config.rs`, `paths.rs`, `hotkeys.rs`: the TOML model, the default template, path resolution, hotkey parsing and validation. `config.rs` holds the built-in registry: `BuiltinSound { name, path ("builtin:<name>", also the decode label), label, bytes }` (`Debug` and `PartialEq` by name only), `BUILTIN_SOUNDS` (`demo` first, then the twelve CC0 sounds in `sources.txt` order), `builtin(name)` (case-insensitive) and `DEMO`. `SoundSource::Builtin(&'static BuiltinSound)` replaces the old demo variant; `resolve` matches the `builtin:` prefix and the name case-insensitively, and an unknown name lists the available ones. The default template lists every registry entry except the demo as a `[[sound]]` with only `name` and `path` (no hotkey, no gain); `stop_all_hotkey` stays. Tests keep the registry honest: every entry decodes, lasts at most 6 s, the total size is under 600 000 bytes, and `SOURCES.md` and `assets/sounds/*.ogg` match the registry. The `[mic]` table resolves into `MicConfig` (gains clamped; a missing or blank `virtual_device` takes `platform::default_virtual_device()` with `platform::default_virtual_device_preference()`, `Some("2ch")` on macOS; a user-set pattern has no preference, so it keeps first-match semantics). `config::update_config(path, edit)` is the one editing sequence (canonicalize, so a symlink writes its target; take the edit lock; read; parse to a `toml_edit::DocumentMut`, leaving an invalid file untouched; run `edit`; write atomically). The edit lock is an exclusive OS file lock (`File::try_lock`, retried for at most 5 s, then the edit fails) on the hidden `.<name>.lock` next to the config, never removed, so the tray's toggle and the settings window's save never both edit the same version and lose one change. `config::set_mic_enabled` is built on it and rewrites only `[mic] enabled`, keeping comments; `settings::save::save_sounds` is the other writer. The write replaces the file atomically: a same-directory temp file with a per-process, per-save name (`.<name>.<pid>.<seq>.tmp`) opened with `create_new`, so it never truncates another writer's temp file, then a rename (the file is never a mix).
  - `actions.rs`: a pure `ActionMap`, the `AudioControl` trait (`play`, `set_master_gain`, `set_mic`, `mic_stopped`, true by default, and `resume_mic`, a no-op by default; `WithVirtualMic` treats a failed `resume_mic` like a failed start) and `apply_config(control, map, capture)`, which sends the master gain and `mic_settings` (`None` when the mic is off; `settings_for` builds them regardless of `enabled`, for `mic-check`; exclusions from `platform::virtual_input_exclusions`). `CaptureGate` turns `platform::microphone_access()` into the `capture` flag: only `Denied` turns it off (the mic sink still plays sounds), with one warning per change while the mic is enabled. `recheck_capture` re-reads the permission and re-applies the mic path only when the capture flag changed since the gate's last decision. `reload` takes the capture decision as a closure over the new `MicConfig`. `toggle_mic` flips `[mic] enabled`, saves it with `set_mic_enabled` (a failed save is logged, the change still applies) and applies the mic path. `mic_status_label` and `mic_toggle_label` are the pure tray texts.
  - `virtual_mic.rs`: `WithVirtualMic`, `VirtualDevice` and the device worker. `DeviceWorker` is a thread that owns the Linux `VirtualMic` (`Option<G>`) and the create function, and answers `DeviceRequest`s in FIFO order (`Create { epoch }` reuses a held device or creates one, `Check { epoch }`, `Release` drops it, `Forget` forgets it) with `DeviceReply`s through an injected callback; the pure `DeviceHost` holds that logic, so tests run it inline. `finish_within` closes the channel and joins for at most `WORKER_FINISH_TIMEOUT` (10 s). That bounds how long quit and mic-off may freeze the event loop; it deliberately does not cover the worst case (a create is a `list`, up to two `unload`s and two `load`s at 3 s each, and a `Release` queued behind it adds more, about 27 s in all). When it fires, the worker is left running (it warns), the device may stay loaded, and the next start unloads it as stale. `WithVirtualMic<C, R>` wraps an `AudioControl` and keeps the mic path state on the event loop thread, sending requests through `DeviceRequests` (the worker, or a recording fake in tests); the device state is absent, creating (with an epoch), present or retired. Every mic-on from no device sends `Create` with a new epoch and returns at once; the path starts only when a current `Created(Ok)` arrives (`on_reply`), and a reply from an older epoch, or for a mic turned off meanwhile, is ignored. A mic-off stops the engine path first, then sends `Release` (while creating too: the FIFO runs it after the create). If the stop left a mic stream running (`mic_stopped` is false), unloading the device could make the server move that stream, live microphone included, to the speakers, so the device is kept as retired until `release_retired` sees the stream ended (then it is released, or taken back by a mic turned on meanwhile, which waits rather than start a second mic path beside the old one). The mic path runs only while this process owns the device: when the create fails (another instance holds the device lock, or the sound server is not up), the failure is logged (first of a streak at error, repeats at debug) and the path waits, because a mic path started without its own device could find another instance's same-named sink and, once that instance unloads it, be moved to the speakers with the live microphone. `waiting_for_device` returns `DeviceWait::Pending` (creating, or waiting for a retired stream; shown as starting) or `DeviceWait::Unavailable` (the create failed; shown as not found, also while it is retried). `restore_device`, at most every `DEVICE_CHECK_INTERVAL` (5 s), sends `Check` for a present device (one at a time) or `Create` after a failed one; a `Checked(false)` stops the path and goes through the same retire decision as a mic-off: if every mic stream ended, it sends `Release` and `Create` at once; if a stream is still running, it warns and keeps the device as retired and vanished (`Retired { vanished: true }`), sending nothing, and once `release_retired` sees the stream ended it sends `Release`, then `Create` with a new epoch if the mic is on (a mic turned on meanwhile does the same instead of reusing the device), or only `Release` if it is off, so a vanished device is never taken back. Turning the mic off forgets a failed create. `shutdown(stop)` stops the engine, sends `Release` (or `Forget` if a stream did not stop: the process ends right after, and the next start unloads the device as stale), then `finish`es the worker.
  - `settings/`: the settings window, a separate process (`sound-babound settings`). Only `view.rs` knows egui (eframe on glow, rfd for the file picker); the rest is plain Rust, so a native window could replace the view.
    - `mod.rs`: `run()` resolves the config with `paths::ensure_default_config`, builds the form (`load_form`: an unreadable file is a form error), starts a status thread that calls `mic_report::status_check` every 1 s and publishes the formatted report in a `Mutex<Option<String>>` (held through a `Weak`, so the thread ends once the window drops it) with a `request_repaint`, and runs `eframe::run_native`, asking for focus once (the macOS bundle is an `LSUIElement` agent). The eframe creator closure also builds the audition controller, `Auditions<ProcessAudition>`, whose waiter threads report exits on an `mpsc` channel and wake the UI with `request_repaint`, and hands it and the receiver to `SettingsApp`. The probe never runs on the UI thread, since a PulseAudio query can block.
    - `form.rs`: the pure `SettingsForm`, built from config text (`loaded` sounds, `stop_all_hotkey`; a file that does not parse is a form error, with editing and Save disabled). Rows are `SoundRow`s (`name`, `path`, `hotkey`, `original: Option<usize>`). `add(path)` pre-fills the name from the stem (a non-UTF-8 path is refused), `remove`, `set_name`, `set_hotkey(KeyCapture)`. `validate()` returns `Vec<Vec<Problem>>` by row (`BlankName`, `InvalidHotkey` for a file hotkey `parse_hotkey` rejects, `DuplicateHotkey` by `HotKey::id()` between rows and against `stop_all_hotkey`, every involved row marked); `can_save()` is false with any problem or a form error. `add_builtin(name)` looks the name up through `config::builtin` (an unknown name is an error) and appends a row with the label as its name, `builtin:<name>` as its path and no hotkey; like `add`, it does nothing on a form that is not editable. `AUDIO_EXTENSIONS` feeds the picker.
    - `keys.rs`: the pure key mapping. `config_key_name` maps egui's `Key::name()` vocabulary to config key names (egui reports numpad digits as the digit row's, so the window never writes `Num0`–`Num9`); `Mods::from_ui` takes egui's flags (a separate Ctrl only on macOS, derived without a cfg); `hotkey_text(mods, key)` gives `Set` (config syntax, fixed modifier order), `Clear` (Escape alone) or `Ignore` (unsupported key, a lone modifier, a non-function key without a modifier or with Shift alone, which is typing). Every `Set` goes through `hotkeys::parse_hotkey`, so the window never writes a hotkey the tray rejects. `UNSUPPORTED_UI_KEYS` (test-only) lists the egui keys it refuses; a `view.rs` test checks every `egui::Key::ALL` against it, which catches egui renames.
    - `save.rs`: the pure `apply_sounds(doc, loaded, rows)`, which refuses if the file's `[[sound]]` entries no longer equal `loaded` (a `[mic] enabled` toggle meanwhile is kept), then rebuilds the array in row order: a row from the file updates `name`, `path` and `hotkey` in its own table (keeping `gain`, unknown keys, comments and decor; no hotkey removes the key), a new row is a new table, removed rows are dropped. The window owns only those three keys. `save_sounds` = `update_config` + `apply_sounds`.
    - `view.rs`: the thin egui view. The hotkey field is a button: a click starts capturing, and while it captures the view swallows every key, text and clipboard event (egui-winit turns CmdOrCtrl+C/X/V into clipboard events, so those shortcuts are never captured, on purpose) and records the key through the pure `keys::capture_text`, as `platform::hotkey_keys()` says: the physical key on macOS (`HotkeyKeys::Position`: global-hotkey registers a virtual key code, a key position), and on Windows and Linux (`HotkeyKeys::Layout`: a virtual key or an X11 keysym, which follow the layout) egui's logical key, or the physical key when the logical one is not a supported key. Save (enabled by `can_save()`) closes on success and shows the error otherwise; Cancel and the close button write nothing. An "Add built-in…" menu button next to "Add sound…" lists `BUILTIN_SOUNDS` by label and calls `add_builtin`. Each row has a Play/Stop button (`Edit::Audition(index)`) beside its hotkey field; the view drains the audition receiver every frame into `Auditions::exited` and shows any message on the message line, and `eframe::App::on_exit` calls `close()`, so Save, Cancel and the close button all kill a running child.
    - `audition.rs`: the audition of a row from the window, always on the default output only. The pure `audition_target(row_path, config_dir)` resolves through `SoundSource::resolve` (a `Builtin` gives its `builtin:` path, a file an absolute path, a relative one against the config's folder; an error is shown and nothing is spawned). The pure controller `Auditions<S: AuditionSpawner>` keeps one audition at a time: `toggle(row, name, path, config_dir)` is the row button (stops the playing row, otherwise resolves through `audition_target` and plays, returning the message to show; the view clears its message line when a play starts), `play(row, target)` stops the current one first and spawns with a new id, `stop()`, `playing()`, `exited(id, ExitReport)` (clears the current one on a matching id and returns the failure message for a non-zero exit; a stale id is ignored), `row_removed(index)` (stops or shifts) and `close()`. `AuditionSpawner::spawn` gives a `RunningAudition` whose `kill` kills and reaps synchronously. `ProcessAudition` runs `current_exe() play --output-only -- <target>` (the command is an injected `fn`, stdin and stdout null, stderr piped) with the `Child` shared as `Arc<Mutex<Child>>`; a waiter thread reads stderr to EOF (last 8 KB), then polls `try_wait` every `WAIT_POLL` (10 ms) without holding the child's lock between polls, so `kill` (lock, kill, wait) can always take it, then sends `(id, ExitReport)` on an `mpsc` channel and calls the repaint callback, so the UI never polls; dropping the handle kills the child, and a failed waiter spawn kills it and fails the spawn. The pure `failure_message` gives the text from the last `Error:` line, else the last non-empty line (skipping a panic's `RUST_BACKTRACE` hint), else the exit status.
  - `settings_process.rs`: the tray's launcher. The pure `SettingsLauncher<S: SettingsSpawner>`: `open(snapshot)` gives `Launched`, `AlreadyOpen` or `Failed` (one window at a time; a failed spawn leaves it closed), and `closed(current)` says whether to reload: only if the config file's bytes (`config_snapshot`, `None` without a readable file) changed since the snapshot taken before the spawn. There is no exit-code protocol. `ProcessSpawner` runs `current_exe() settings` (stdin null, stdout and stderr inherited); a waiter thread, started before the child and handed it over a channel, waits on it and sends `UserEvent::SettingsClosed`.
  - `tray_app.rs`: the tao event loop, the tray, hotkey registration and reload. The menu has a disabled mic status line and a "Mic to call: on/off" toggle. While the mic is enabled, the loop wakes every 1 s (`ControlFlow::WaitUntil`, through the pure `mic_poll`), calls `resume_mic` (a deferred mic start), `recheck_capture` (so a permission answered or changed while the app runs takes effect), calls `restore_device` while the mic status is not found (the mic sink reports it, or the mic path waits for the device), and updates the status text only when it changed; it also polls, calling `release_retired`, while a retired device waits for a mic stream to end; otherwise, with the mic off, it stays on `Wait`. The device worker's reply callback sends each reply into the loop as `UserEvent::Device` through an `EventLoopProxy` (replies sent before the loop runs wait in its queue); the loop hands it to `WithVirtualMic::on_reply` and refreshes the status line. The pure `tray_mic_status` maps the virtual mic's wait state to the tray's `MicStatus`: a pending device shows as starting, a failed create as not found, and otherwise the engine's status stands. `Hotkeys` goes through a small `HotkeyBackend` trait, so registration and reload can be tested with a fake. The menu's "Settings…" item (above "Reload config") opens the settings window through `SettingsLauncher`; the tray pauses its hotkeys before the spawn (`Hotkeys::pause` unregisters them, and a reload while paused registers nothing; a failed spawn `resume`s with the current board's hotkeys), because the OS hands a global hotkey to the tray before the window could see it. On `SettingsClosed` it reloads first if the launcher says the file changed, then always `resume`s with the current board's hotkeys. Quitting the tray leaves an open settings window running.
  - `test_support.rs` (`#[cfg(test)]`): `TempDir`.

## Realtime rules

These apply to every cpal data callback (the monitor and mic sink outputs and the capture input) and to everything `Mixer::render`, `PassthroughShared::write` and `PassthroughReader::read` reach:

- No allocation and no freeing. Never drop the last `Arc` of a `Sound` there.
- No blocking lock. Use only `try_lock`, and output silence when it fails.
- No I/O and no `tracing` macros.
- The only `push` calls allowed are on the lock-free `ArrayQueue`s.

Passthrough rules:

- The ring is the preallocated `ArrayQueue<f32>` in `PassthroughShared`, mono, 0.5 s at 192 kHz. The capture callback downmixes by averaging, then `force_push`es; a displaced sample counts as an overrun. Past the high mark (the published target + `max(HIGH_MARK_MARGIN (50 ms), capture block + BLOCK_MARGIN)`) the writer pops the oldest samples and counts an overrun too. Every write bumps the capture heartbeat.
- Adaptive target: the writer records its largest capture block (`fetch_max` in `write`), and the reader its largest sink block. `cpal_sink::render_into` announces the whole callback's frame count through `Mixer::begin_callback` → `PassthroughReader::note_block` before rendering `SCRATCH_FRAMES` chunks (the reader cannot tell a long callback from back-to-back chunks); `read` also raises it to its length, and `Mixer::configure` resets it. The effective target, in capture-rate samples, is `max(TARGET_FILL, sink block (converted from the sink rate) + capture block + BLOCK_MARGIN (5 ms))`, at most half the ring: one block of each side, because when the two callbacks' order slips, the fill seen before a read drops by a whole capture block. It is computed before the priming check, and the reader publishes it to an atomic. The writer's high mark is `published target + max(HIGH_MARK_MARGIN, capture block + BLOCK_MARGIN)`. The writer never uses less than the fallback target `max(TARGET_FILL, capture block + BLOCK_MARGIN)` (at most `MAX_TARGET`, `fallback_target`), for the high mark and the trim-back level: in place of a target before the reader has published one, and above a target a running mic sink published before the first capture block. So the first two capture blocks never trim (the high mark is then at least two blocks plus two margins). The controller steps once per announced callback (once per read outside one), on the error against the effective target.
- `begin_capture(rate)` empties the ring, forgets the capture block and the published target, stores the rate and bumps the generation. Only a capture build calls it, before its stream starts. The reader resets and re-primes on a generation or rate change. `set_sink_rate` (called by `Mixer::configure`) re-primes at every call, since the new stream's target may be higher: a changed rate also resets the resampler and the controller, while the same rate keeps the learned correction, integral and fill error (the clock ratio is the same) and only re-seeds the EMA.
- `PassthroughReader` lives in the mic `Mixer` and runs inside `render`. It outputs silence until the fill reaches the effective target (priming). An underrun mid-block counts, outputs silence for the rest of the block and re-primes.
- Drift controller: linear interpolation at `capture_rate / sink_rate * (1 + correction)`. The correction is a PI controller (`KP`, `KI`) on an EMA-smoothed fill error, clamped to `MAX_CORRECTION` (±0.2 %). Changing it must keep the simulated-clock drift tests passing (10 simulated minutes, 480- vs 512-frame blocks, 48k/48k, 44.1k to 48k, ±200 ppm: fill within target ± 20 ms after 5 s, no underruns, no overruns), and so must the long-block drift tests (2048/2048, 480/2048 and 2048/480 at 48k/48k, 4096/4096 at 48k/48k, 480/2048 at 44.1k to 48k and at 48k to 44.1k: fill within the effective target ± (20 ms + one capture block), late correction within 20 ppm of the clock ratio, except 2048/2048 and 4096/4096, where the correction comes in a burst at each slip and its mean from 60 s on must be within 20 ppm plus one capture block over that span). The 4096/4096 case is the one where `capture block + BLOCK_MARGIN` exceeds `HIGH_MARK_MARGIN`, so the high mark's capture-block branch is exercised.
- The monitor's mixer has no reader, so it can never carry the microphone.

Pending-release rule: every `Sound` that leaves a voice (finished, evicted or stopped) is pushed onto the garbage queue. `drain_garbage()` frees those sounds on the supervisor thread. If the garbage queue is full, the `Sound` goes into a preallocated pending-release slot (`2 * MAX_VOICES` slots). Those slots are retried at the start of every render. Commands are popped only while at least `MAX_VOICES` slots are free, so every release always has somewhere to go. A finished voice with no free slot stays parked, silent and uncounted, until a slot frees up.

## Mixer handoff invariant

The mixer lives in `Arc<Mutex<Mixer>>`. To rebuild, the supervisor drops the old sink and then calls `StreamFactory::build`, so `build` only ever runs while no stream exists. `build` may lock the mixer freely, and it must call `configure(rate, channels)` before it starts the stream. Once the stream runs, only its callback touches the mixer, through `try_lock`, so that lock never contends. `configure` keeps the voices and their source positions, which is how playback continues across a rebuild.

Only a running stream drains the command queue. `MixerShared::output_active` (`Engine::has_output`) reports whether a stream runs; the supervisor sets it only after `build` returns.

Play grace window: `Engine::play` checks `MixerShared::accepts_plays(now)` per path, which is `output_active || now < grace_until`. When the supervisor drops a live stream for a rebuild, it opens the window for `Timings::play_grace` (1 s); a teardown with no live stream never opens it. So a press made while the output switches devices is accepted and played by the replacement stream, but presses made with no device, or during the initial build or a build after a failed one, are rejected (return false) and never start late when a stream comes up. `grace_until` is an atomic count of nanoseconds since an epoch `Instant` the `MixerShared` owns (0 means closed). A rebuild from a live stream keeps the command queue: plays accepted while the old stream ran or inside the window, including one whose push races the teardown (the check and the push are not atomic), are applied in order by the new stream, like the voices it continues.

While no stream exists and the window is closed (failed build, retry backoff, initial start), each supervisor loop, and every build started with no stream, locks the mixer, which cannot contend then, and calls `Mixer::apply_offline`. It drops any play that passed the check just before the stream went away, or inside a window that expired without a new stream, and it still applies `StopAll`, `SetMasterGain` and `SetPathGains`. While the window is open, that offline purge is skipped. The headless `play` waits for `has_output` before queuing its play, and once the mixer reports no voices it keeps the stream up for the measured output latency (`Engine::output_latency`: the cpal callback timestamps' `playback - callback` plus the duration of the callback's buffer, so it reaches the last written frame; capped at 5 s) plus a 200 ms margin, so the device buffer is heard.

## Rebuild policy

A rebuild is an audible gap, so not every event triggers one. Events are debounced on the trailing edge, 200 ms after the last event.

Three streams, three roles (`StreamRole`): `Monitor` (the default output, always running), `MicSink` (the virtual device's playback side, matched by name) and `Capture` (the default input, feeding the passthrough). Each runs under its own instance of the one generic supervisor (`spawn_supervisor`), with its own factory, endpoint and watcher; only the factory and the policy differ. A rebuild of one role never touches another.

The classification is `DeviceEvent::rebuild_policy(role)`:

| Event                  | Monitor           | MicSink           | Capture           |
|------------------------|-------------------|-------------------|-------------------|
| `DefaultOutputChanged` | Always            | Ignore            | Ignore            |
| `DefaultInputChanged`  | Ignore            | Ignore            | Always            |
| `DeviceListChanged`    | IfIdentityChanged | IfIdentityChanged | IfIdentityChanged |
| `DeviceStateChanged`   | IfIdentityChanged | IfIdentityChanged | IfIdentityChanged |
| `DeviceRemoved`        | IfIdentityChanged | IfIdentityChanged | IfIdentityChanged |

- Always rebuild, for every role: a forwarded stream error and a stalled callback heartbeat. The cpal error callback filters stream errors first (`cpal_sink::needs_rebuild`). `Xrun` and `RealtimeDenied` are dropped, because the stream keeps running and a rebuild would only add a gap. A forwarded error carries a `StreamErrorKind`: `DeviceChanged` (cpal's `ErrorKind::DeviceChanged`, routine on a default switch) is logged at debug, `Other` at warn (`stream_error_level`); both rebuild.
- Startup grace: a new stream has `Timings::startup_grace` (10 s) to deliver its first callback, measured from the end of `build`. The heartbeat is read just before `build` as the baseline, so a callback that lands between `build` and the first check counts as started. Once the heartbeat has moved past the baseline, the stall deadline is `last beat + stall` (2 s). `next_deadline` returns the same deadlines.
- `IfIdentityChanged`: the supervisor re-queries the identity a build would pick now (`StreamFactory::current_identity`: the default output, the matched mic sink or the chosen input) and rebuilds only if it differs from the identity the stream was built on (`None` vs `Some` counts as different). Otherwise it logs the event at debug and drops it.
- With no active stream (initial start, or the 1 s retry backoff after a failed build), every non-ignored event rebuilds.
- Build failures are logged through the pure `FailureLog`: warn on the first failure of a streak and when the error changes, debug for repeats, info when a build succeeds after failures.
- Each supervisor publishes a `StreamStatus` (Starting, Running, Failed) in a control-thread-only mutex that no callback touches; `Engine::mic_status` is built from those.
- Never cache a device. Every build and every identity check re-queries the devices.

The timing logic is the pure `SupervisorCore`, tested with a fake clock (`Timings`: debounce 200 ms, retry 1 s, stall 2 s, startup grace 10 s, play grace 1 s, stop timeout 3 s).

## Platform code

Platform code lives only in:

- `crates/engine/src/watcher/{macos,windows,linux}.rs`
- `crates/engine/src/platform/{macos,windows,linux}.rs`
- `crates/app/src/platform/{macos,windows,linux}.rs`

Each set is selected by `#[cfg(target_os = ...)]` in its `mod.rs`. Shared code contains no `cfg(target_os)`. The only `target_os` cfgs outside the per-OS files are in those `mod.rs` files: the watcher selection (`platform_watcher(role)` comes from `linux.rs` on Linux and is role-independent elsewhere), `NoopWatcher` (built only outside macOS and Windows), dead-code allows on `poll`, `inputs` and the engine's `platform::shared_host` (only Linux uses them; they are tested on every OS), the engine host selection (with a default-host fallback for other OSes), the app's pure Linux helpers (`cfg(any(target_os = "linux", test))`, so they are tested on every OS) and `Ok(None)` virtual-mic fallback, dead-code allows on variants only some OSes construct (`MicrophoneAccess::Undetermined`/`Unknown`, `HotkeyKeys::Position`/`Layout`), and a dead-code allow on `EventSender::send`, which only the macOS, Windows and Linux watchers call. cpal's `pulseaudio` feature is enabled for the Linux target only.

The macOS watcher uses `objc2-core-audio` rather than `coreaudio-sys`, which would need libclang. On Linux the monitor watcher is a no-op, because ALSA `default` follows PipeWire/PulseAudio. The mic sink ignores default changes, but cpal opens its PulseAudio stream without `dont_move`: when the virtual device is unloaded while the server keeps running, the server moves the stream to the default sink without an error, and the call mix (live microphone included) would play on the speakers. So the Linux mic sink watcher polls the PulseAudio host's output list every 1 s (same shared host and handle rules as the capture poller below) and sends `DeviceListChanged` on any change; the identity check then finds the device gone, drops the stream and reports not found, which lets the tray create the device again. The capture does not get the ALSA `default` behavior either: cpal's PulseAudio host resolves the default source when the stream is built and stays on it. So the Linux capture watcher polls the PulseAudio host's default input and input list every 1 s through `poll.rs` and `inputs.rs`. It sends `DefaultInputChanged` when the default input's identity changes and `DeviceListChanged` when only the list does. The list matters for the fallback: when the capture runs on the last physical input because the default is the excluded virtual device, and that input goes away, the server moves the stream to the default source without an error; the list change makes the supervisor check its identity, which then refuses the build with `FeedbackExcluded`. It uses the shared mic host (never one of its own), keeps its handle between polls and asks the server afresh each poll; it asks `mic_host()` again only after the connection fails (in the same poll, which reconnects the shared host) or while `mic_host()` falls back to another host. A host of its own, per poll or per poller, would leak a thread and a connection each time it dropped, because the pulseaudio client's reactor thread is not woken when the client drops.

## No real audio from agents

Agents (automated runs, ralphex, CI) must never play audio through a real device, change the system default input or output, change the system volume, or open the microphone. Concretely:

- Do not run `sound-babound play` (with or without `--output-only`), the tray app or `mic-check` against real devices, and do not create the Linux virtual device (`pactl load-module`). Never click Play in the settings window: it starts `play --output-only` on the real default output.
- No automated run opens a window: never run `sound-babound settings` or spawn the settings process. Tests of the launcher use a fake spawner, and `ProcessSpawner`'s own tests run the test binary with `--list`. Audition tests do the same: `Auditions` is tested with a fake spawner, and `ProcessAudition` with the test binary and `--list`.
- Real-device checks are `#[ignore]` tests (`cargo test -p babound-engine -- --ignored`) that only a human runs. The smoke test `cpal_sink::tests::smoke_builds_real_streams` builds the monitor and, if `BABOUND_MIC_DEVICE` (default `platform::SMOKE_MIC_PATTERN`) matches an output, the mic sink and a capture on the real default input. It plays nothing but opens the microphone. On Linux its mic part needs the tray running with the mic on, since only the tray creates `sound_babound_sink`.
- `scripts/bundle-macos.sh` only builds and signs; running it is fine. Launching the bundle is not.
- Everything else is tested with fakes. One exception on Linux: the non-ignored `watcher::tests::platform_watcher_*` tests start the capture's input poller and the mic sink's output poller, which connect to the running PulseAudio or pipewire-pulse server and only read the default source, the input list and the output list. They open no stream and play nothing; without a server they fall back to ALSA.

## Conventions

- Edition 2024, workspace resolver 3.
- Dependencies, smallest feature sets that build on all three targets: `eframe` (app only, `default-features = false` with `glow`, `default_fonts`, `wayland`, `x11`; no accesskit, no persistence) and `rfd` (app only, `default-features = false` with `xdg-portal`: pure Rust on Linux, no gtk and no pkg-config, so the stub-pkg-config cross-check keeps working) for the settings window; `socket2` and `libc` (engine, Linux target only) for the PulseAudio probe's bounded non-blocking connect; `pulseaudio` (engine, Linux only) for the probe's handshake.
- No `unwrap`/`expect` outside tests.
- Typed `thiserror` errors in the engine (`LoadError`, `BuildError`, `StartError`, `WatcherError`); `anyhow` in the app.
- Tests use fakes (`FakeSinkFactory`, `FakeWatcher`, a recording `AudioControl`, a fake `HotkeyBackend`) and need no audio device. The one real-device smoke test is `#[ignore]`.

Run all of these after every change. They must all be clean:

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets          # zero warnings
cargo test --workspace
cargo check --workspace --target x86_64-pc-windows-msvc
```

A Linux cross-check from macOS is blocked by `alsa-sys` pkg-config. It only type-checks if you give it a stub `PKG_CONFIG` and set `PKG_CONFIG_ALLOW_CROSS=1`.
